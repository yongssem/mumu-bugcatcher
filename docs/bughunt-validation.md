# 채집 모드 조작·안정성 정비

## 변경

- 실제 서비스 중인 `BugHunt`를 React 오버레이와 독립된 `BugHuntEngine`으로 분리했다. 기존 공룡용 `GameEngine`을 수정하는 대신 실제 채집 경로를 고쳤다.
- 키보드/방향키, 달리기, 단발 점프, 마우스 잠금과 드래그 대체 조작, 길게 누르는 채굴, 액션 재사용 간격을 통합했다.
- 모바일은 화면 너비와 무관하게 터치 기기에서 4방향 아날로그 조이스틱을 표시한다. 이동·시점·액션은 서로 다른 포인터를 사용하며 취소/포커스 해제 시 모두 놓는다.
- 시작·일시정지 화면, 읽을 수 있는 가로 폰용 조합창, 조준 대상/남은 채굴 횟수, 제작 후 잠자리채 자동 선택을 추가했다. C/E 반복 입력에 의한 조합창 연속 토글을 막았다.
- 창 전환, 숨겨진 탭, Escape, 조합창에서 이동·곤충 AI·투사체·재생성 타이머를 함께 정지한다. 채집 화면을 나가면 입력 리스너·예약 작업·GPU 소유 자원을 해제한다.
- 몸체 너비를 반영해 장애물과 블럭에 충돌한다. 이동을 작은 시간 단위로 나누고 벽을 따라 미끄러지며 한 칸 계단만 자동으로 오른다.
- 6종 자원과 잠자리채용 잎·나뭇가지를 항상 배치한다. 장식이 자원 자리를 먼저 차지하지 않으며, 채굴한 자원은 예약된 자리에서 다시 생긴다. 높은 풀 벽은 가장자리 위주로 줄였다.
- 조준 방향에 가까운 보이는 대상을 선택하며 장애물/설치 블럭을 관통한 채굴·포획을 막는다. 곤충이 장애물 안으로 기어들어가는 경우도 막았다.
- 기존 도감/인벤토리/집 저장 키를 유지했다. 잘못된 숫자·도감 항목·존재하지 않는 전시 곤충을 정리하고, 이미 가진 영구 잠자리채의 중복 제작을 막았다.
- 저장 차단/용량 부족 시 세션 메모리에 성과를 보존하고 화면에 경고한다. 저장 차단 때문에 BGM 모듈 로딩부터 실패하던 문제도 고쳤다.
- 설치 블럭은 `mumubug:hunt-world:v1`에 서식지별로 보존한다. 시작 안전 구역·경계·자원 예약 구역에는 재료 소비 전에 설치를 거부한다.
- 집/메뉴에서 연 도감은 닫으면 원래 화면으로 돌아간다. 도감은 현재 화면 크기에 맞는 뷰어 하나만 구동하며 퀴즈가 열리면 뒤의 뷰어를 멈춘다. 공유 복셀 큐브를 잘못 해제하던 문제도 고쳤다.

## 검증

- `npm test`: Node 회귀 테스트 31개 통과.
- `npm run build`: 프로덕션 빌드 통과.
- `git diff --check`: 통과.
- 별도 코드 리뷰에서 지적한 중앙 블럭 유실, 잘못된 전시 ID 크래시, 도감 복귀 경로 문제를 각각 실패하는 테스트로 재현한 뒤 수정했다.
- Chrome 자동화 `npm run test:browser`: 검사 18개 통과. PC 1280×800, 터치 폰 844×390/390×844, 태블릿 1180×820/820×1180을 사용했다. 터치 지원 PC의 마우스 시작과 포인터 잠금 거절 환경도 포함한다.
- 실제 마우스 길게 누르기 채굴 → 잠자리채 제작 → 대형 곤충 마취/포획 → 도감 저장 → 집/메뉴 복귀를 확인했다. 터치 두 손 동시 조작/취소, 4개 서식지 반복 입장, 설치 블럭 복원, localStorage 읽기/쓰기가 전부 차단된 상황도 확인했다.

## 재실행

```sh
npm ci
npm test
npm run build
npm run dev -- --host 127.0.0.1 --port 5175
# 별도 터미널에서
npm run test:browser
```

브라우저 검사는 설치된 Chrome을 사용한다. `TEST_URL`로 개발 서버 주소, `TEST_OUTPUT_DIR`로 스크린샷 경로, `PLAYWRIGHT_CHANNEL`로 브라우저 채널을 바꿀 수 있다. 기본 스크린샷 경로 `test-results/`는 Git에서 제외된다. 개발 모드의 기존 디버그 API는 테스트 배치 준비에만 사용하며 프로덕션에는 포함하지 않는다.

## 검증 범위

실물 iOS/Android 기기의 GPU·브라우저 동작은 별도 확인이 필요하다. Three.js를 포함한 기존 단일 번들에 대한 Vite의 500KB 경고는 남아 있으며 빌드는 성공한다. 저장 자체가 차단된 기기에서는 창을 닫은 뒤 새 성과를 영구 보존할 수 없으므로 이를 화면에 명확히 알린다.

## 모바일·태블릿 가로 화면 전용

터치 기기의 세로 화면에서는 랜딩·메뉴·채집을 모두 가리고 배경 DOM을 inert 처리한다. 플레이 중 세로 전환 시 같은 엔진을 유지한 채 일시정지하고, 키보드·조이스틱·액션 입력을 해제한다. 가로로 돌아오면 계속하기로 재개한다. 폰/태블릿 양쪽에서 회전과 월드 보존을 검증했다.

시작/전체화면 버튼은 전체화면 진입 후 `screen.orientation.lock('landscape')`를 시도한다. 브라우저가 잠금을 지원하지 않거나 거절하면 세로 차단과 직접 회전 안내를 유지한다. 모든 브라우저에서 OS 방향을 강제한다고 가정하지 않는다. 잠금 순서·API 미지원/거절·PC 방향 잠금 제외도 단위 테스트로 검증했다. [ScreenOrientation.lock — MDN](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)

## PC 마우스 시점

탐험 계속하기를 마우스로 누르면 기기의 터치 지원 여부와 관계없이 PC 조작으로 시작한다. 포인터 잠금을 요청하고 커서를 숨기며, 마우스 버튼을 누르지 않은 이동만으로 시점이 바뀐다. 잠금이 거절되거나 API가 없어도 캔버스 위에서는 마우스 이동을 그대로 시점 입력으로 사용한다. Esc/조합/포커스 해제/화면 종료 시 커서를 복원한다. 터치 드래그는 별도 경로로 유지하며 입력 장치 전환 시 남은 액션과 잠금을 정리한다.

일반 PC, 터치 지원 PC에서 실제 마우스 이동과 버튼을 누르지 않은 상태를 확인했다. 포인터 잠금 Promise 거절과 구형 pointerlockerror 이벤트도 검증했다. 브라우저 잠금 API의 제약은 [MDN requestPointerLock](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestPointerLock)을 따른다. 잠금이 거절되는 내장 브라우저에서는 화면 좌우 가장자리에서 연속 회전을 추가해 커서가 화면 끝에 닿아 약 90도에서 멈추던 문제를 해결했다. 이 대체 조작은 화면을 벗어나거나 일시정지하면 즉시 멈추고, 실제 포인터 잠금이 성공하면 중복 적용하지 않는다. 잠금 거절 브라우저에서 좌우 각각 360도 이상 회전을 검증했다.

## 새 오리지널 BGM

기존 무무다이노 음악 7개를 배포 폴더에서 제거하고, 새 악보와 자체 합성 악기로 만든 32마디 3곡을 적용했다. 외부 음원·샘플은 사용하지 않았다. 기존 원본은 Git 이력에서 복구 가능하다. 재생성 가능한 소스는 `scripts/compose-bgm.py`다.

| 곡 | 화면 | 속도 | 길이 | MP3 용량 |
| --- | --- | --- | --- | --- |
| 이슬 정원의 아침 | 랜딩·메뉴·서식지 선택 | 100 BPM | 76.80초 | 1,347,733바이트 |
| 풀잎 사이 탐험 | 채집·미리보기 | 112 BPM | 68.57초 | 1,211,032바이트 |
| 작은 곤충의 집 | 집·도감 | 88 BPM | 87.27초 | 1,529,717바이트 |

칼림바·마림바·벨 주제와 플루트 교대, 부드러운 베이스·패드·작은 타악기로 구성했다. 잔향을 루프 앞머리로 순환시켰고, 44.1kHz 스테레오 MP3로 출력했다. 음원 합계는 26,530,698 → 4,088,482바이트(84.59% 감소)다. 기존 음소거·볼륨 설정을 유지하고 같은 곡으로 화면을 오갈 때 처음부터 다시 시작하지 않는다.

브라우저에서 3곡 모두 실제 디코딩, 무음/클리핑 여부, 루프 경계 차이를 수치로 확인하고 채집/집 화면에서 재생 시간 증가와 곡 전환을 검증했다. 이 검증은 음질의 실제 청취 평가를 대체하지 않는다.
